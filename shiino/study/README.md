# shiino_勉強記録

React + Vite で作った、科目ごとの勉強時間を記録するアプリ。

## 起動方法

```bash
npm install   # 初回のみ
npm run dev   # 表示されたURLを開く
```

他のアプリと同時に動かすときは `npm run dev -- --port 5176` のようにポートを指定する。

## 画面の流れ

```
タイトル ──START / Enter──> メニュー ──アイコンを押す──> 機能の画面
                              ^                            |
                              └────「メニューに戻る」/ Esc ──┘
```

メニューに並ぶアイコンの順番は `lib/features.js` で決めている。6つなので1行3つ・2行にちょうど収まる。

各ページは、その機能を先頭に置き、続けて「そこで一緒に見たくなるもの」をそえる。

| ページ | 並べるカード |
| --- | --- |
| 計測 | 計測 → 今のペース → 追加した記録 |
| 合計 | 合計 |
| 記録 | 記録 → 手入力で追加 |
| マイルストーン | マイルストーン |
| 目標 | 目標 → 今のペース → 追加した記録 |
| 科目 | 科目 → 科目別の累計 |

**一覧・集計を見せるカード（記録・合計・マイルストーン）は、それぞれの画面にしか置かない。**
あちこちに出ると、どこが本家か分からなくなるため。
そえるのは「今のペース」「追加した記録」「科目別の累計」といった、
そのページの操作を助ける小さいカードだけにしている。

どの画面も横幅は752pxでそろえ、中身は画面の上下中央に置く。
カード同士の間隔は24px（`.screen-body` の `gap`）。2〜3枚並ぶ画面が多いので、
詰まって見えないよう広めに取ってある。
中身が画面より高いときは、そのまま下に伸びて普通にスクロールできる。

## できること

- **タイトル画面**: 開くと最初に出る。STARTまたはEnterでメニューへ。
  今日の勉強・連続日数・到達段階・目標の達成度の4枚と、直近7日の棒グラフを出して、
  続きから始められるようにする。計測中は、科目名と経過時間の帯を1秒ごとに更新して出す
  4枚は「値・帯・補足」の同じ形（今日＝今週に占める割合、到達段階＝次の段階までの進み具合、
  目標＝達成度）。連続日数だけ帯にする対象が無いので、補足で状態を伝える。
  カード列と棒グラフは幅830pxでそろえてある
- **メニュー**: 機能ごとのアイコンと名前を1行3つ・2行で並べる。押すとその機能の画面に移る。
  画面が狭いか低いときは、タイルとアイコンを小さくして1行4つに詰める。
  計測したまま別の画面に移れるので、計測中は経過時間のバッジを1秒ごとに更新して出す。
  目標を決めているときは、開かなくても分かるように達成度のバッジを出す。
  選ぶのはクリックのみ（キーボードのショートカットは持たない）
- **計測**: 科目を選んで開始／一時停止／停止。停止した時点で記録に残り、すぐ下の「追加した記録」に出る。
  8時間を超える計測は、止め忘れの可能性があるので記録するか破棄するかを確認する
- **休憩**: 一時停止しているあいだは休憩として数え、勉強時間と分けて記録に残す。
  記録の一覧と合計に「休憩 ◯分」として出る（勉強時間には足さない）
- **合計**: 今日／今週／全期間で切り替え。科目別の内訳と直近7日を棒グラフで表示（`WeekChart`）。合計の画面だけに出る。
  休憩の合計を横に添える
- **記録**: 日付ごとにまとめて表示。1件ずつ編集（科目・日付・時間）・削除でき、手入力で足せる。記録の画面だけに出る。
  行は「時刻 → 科目 → 時間 → 操作」の順にそろえ、時間は右端で桁を合わせる
- **マイルストーン**: 累計の勉強時間に応じて、9段階を順に到達していく。マイルストーンの画面だけに出る
- **目標**: 期限と時間を決めて、勉強したぶんを積み上げる。期限や科目を分けていくつでも同時に持てる
- **科目**: 追加・削除。色を8色から選べる。**削除しても記録は消えない**（「（削除された科目）」として残る）
- **手入力**: 計測し忘れた分を、日付と時間を指定して後から追加。記録の画面の中にある。
  足したぶんは一覧の中で色が付き、見える位置まで自動でスクロールする
- **追加した記録**: 計測・目標の画面にそえる直近5件。今足したぶんを色付きで示す。
  その場で削除もできるので、押し間違えたらすぐ取り消せる
- **今のペース**: 計測・目標の画面にそえる、今日／今週／1日あたり（直近7日）。
  目標の「1日あたり◯◯必要」と並ぶので、間に合っているかがその場で分かる
- **科目別の累計**: 科目の画面にそえる、科目ごとの全期間の合計。
  棒はいちばん多い科目を基準にする（合計に対する割合より、科目どうしの差が見やすいため）

## マイルストーン

累計の勉強時間で到達する段階が決まる。段階は9つ。

| 段階 | 必要な累計 | | 段階 | 必要な累計 |
| --- | --- | --- | --- | --- |
| スタート | 0時間 | | 上級 | 80時間 |
| 入門 | 5時間 | | 熟練 | 150時間 |
| 初級 | 15時間 | | 達人 | 250時間 |
| 中級 | 40時間 | | 名人 | 400時間 |
| | | | 極み | 600時間 |

目盛りは等間隔で描き、現在位置のマークだけが区間の進み具合に応じて動く
（時間どおりの間隔にすると、最初のほうが潰れて読めなくなるため）。

## 目標

期限・時間・対象科目を決めて設定する。

- **決めたあとの勉強だけが数えられる**（決める前に済ませた分は入らない）
- 対象科目を選ぶと、その科目の勉強だけが効く（「すべての科目」も選べる）
- 残り時間と、期限に間に合わせるために必要な「1日あたりの時間」を表示
- 目標に届くと**達成**、届かずに期限を過ぎると**期限切れ**
- 期限や科目を分けて、いくつでも同時に持てる（期限が近い順に並ぶ）
- 削除に確認は出さない。名前・期限・時間を決め直せばすぐ作り直せるため
  （記録の削除に確認が無いのと同じ扱い）

達成度（`goalProgress`）はタイトル画面とメニューの両方に出す。途中は `35%` のような数字、
決着後は `達成` / `期限切れ` と言葉で出し、期限切れだけ赤くする。
複数あるときは、期限がいちばん近い1件を代表にして「ほか◯件」を添える。

帯は達成したぶんが左から伸びる。タイトル画面の達成度と向きをそろえてある。

## 連続日数

タイトル画面の「連続日数」の札。今日から1日ずつさかのぼって、記録のある日が続いている数を数える。

- 同じ日に何件記録があっても**1日**と数える
- **今日まだ記録が無いときは、昨日を起点にする**。その日のうちに勉強すれば途切れないので、
  まだ切れたことにはしない。この場合だけ補足を `今日はまだ` に変え、色を付けて伝える
- 0日のときは `なし` と出す（列を欠けさせないため、札そのものは残す）

## 記録の保存先

保存先はブラウザの localStorage だけ。次のどれかで消えるので注意する。

- ブラウザの「閲覧データを削除」
- 別のPC・別のブラウザで開く
- シークレットウィンドウで使う

書き出し・読み込みの機能は持っていない。

## 設計のメモ

- 記録は `{ id, subjectId, seconds, breakSeconds, startedAt }` の形。科目名ではなく **id で参照**しているので、
  科目名を変えても過去の記録が壊れない。`breakSeconds` が無い古い記録は 0 として扱う。
- 集計は保存せず、記録から毎回計算する。合計値を別に持つと、記録を消したときにずれるため。
- 日付は `YYYY-MM-DD` の文字列で扱う。この形式なら文字列のまま大小比較でき、
  「今週かどうか」の判定が単純になる（`toISOString()` はUTCになるので使っていない）。
- 科目を削除すると、その科目の記録もまとめて消える。消える件数を確認ダイアログで伝えてから実行する。
- 今どの画面かは `App.jsx` の `screen` 1つで持つ。`"title"` → `"menu"` → 機能のキー、と入る値が変わる。
  画面ごとに別のフラグを持つと組み合わせが増えるので、1つの値で表している。
- 記録や計測中の状態は画面をまたいで `App.jsx` が持ち続ける。
  そのため、計測を始めたまま別の機能を見に行っても計測は止まらない。
- 経過時間は `App.jsx` で1秒ごとに数え直し、計測画面・メニュー・タイトル画面に同じ値を渡す。
  画面ごとにタイマーを持たないので、どこで見ても同じ秒数になる。
  計測中の状態は localStorage に残るため、閉じて開き直すと**タイトル画面から続きの時間が見える**。
- **科目を消しても記録は消さない**。積み上げた時間まで失われるほうが困るため。
  記録は科目名ではなく id を持っているので、科目がいなくなった記録は
  「（削除された科目）」と表示されるだけで、集計にはそのまま入る。
- 計測中の状態は `{ subjectId, startedAt, accumulated, since, breakAccumulated, pausedAt }`。
  勉強と休憩をまったく同じ形で数えている。
  - 勉強 … `accumulated + (now - since)`。一時停止すると `accumulated` に畳んで `since` を null に
  - 休憩 … `breakAccumulated + (now - pausedAt)`。再開すると `breakAccumulated` に畳んで `pausedAt` を null に

  `since` と `pausedAt` は必ずどちらか片方だけが入る。
  古い形（`accumulated`/`since`/`breakAccumulated` が無い）は `loadRunning` が読み替えるので、
  更新前に計測していても止まらない。
- 休憩は記録に `breakSeconds` として残すが、**集計には入れない**。
  勉強時間を聞かれて休憩ぶんが混ざっていると、記録として使えなくなるため。
- 目標は配列で持つ。「ボス戦」と呼んでいたころの `study.bosses` と、
  1件だけだったころの `study.boss` は `loadGoals` が読んで移し替える。
- 記録の一覧は、休憩の有無で勉強時間の位置がずれないよう、時間のまとまりを固定幅の枠に入れている。
  縦にそろっていないと、どの日にどれだけやったか目で比べられないため。
  狭い画面（560px以下）では科目名が潰れるので、そこだけ固定幅を外している。
- 記録の追加は `App.jsx` の `addRecord` 1か所に集めてあり、そこで直前のidも覚える。
  計測でも手入力でも同じ場所を通るので、どちらから足しても同じように色が付く。
- 「追加した記録」は日付順ではなく**追加した順**で新しいほうから並べる。
  日付順にすると、過去の日付を手入力したときに、今足したぶんが下に埋もれて見えなくなるため。
- 記録の画面は日付順に並ぶので、そちらでは足したぶんに色を付け、
  見える位置まで自動でスクロールして同じ問題を防いでいる。
